## Insurance: регрессия

[Ноутбук](../notebooks/insurance_regression.ipynb) · [Метрики CSV](../results/insurance_regression_metrics.csv)

Источник фактической загрузки — [insurance.csv в stedy/Machine-Learning-with-R-datasets](https://raw.githubusercontent.com/stedy/Machine-Learning-with-R-datasets/master/insurance.csv). В исходной работе также указана [страница набора на Kaggle](https://www.kaggle.com/datasets/mosapabdelghany/medical-insurance-cost-dataset/data). Код получает CSV по URL; локальный датасет не требуется. Результат нового запуска зависит от доступности и содержимого этого внешнего файла.

- 1338 строк; target `charges`, признаки `age`, `sex`, `bmi`, `children`, `smoker`, `region`.
- Random split 80/20, seed 42: 1070 train / 268 test.
- Числовые признаки масштабируются StandardScaler; категории кодируются OneHotEncoder; преобразования обучаются в sklearn Pipeline.
- OLS test: RMSE **5796,28**, MAE **4181,19**, R² **0,7836**.
- Lasso: четыре значения `alpha`, GridSearchCV с `cv=5`, scoring R². После мягкой IQR-фильтрации удалена одна train-строка; test RMSE **5806,32**, R² **0,7828**. После агрессивной фильтрации с учётом target удалено 116 train-строк; test RMSE **7458,81**, R² **0,6416**.

![Сохранённые распределения target на train](../results/insurance_train_distribution.png)

![Сохранённые предсказания OLS на test](../results/insurance_ols_actual_predicted.png)

Ограничения: ранние EDA-графики используют весь набор, далее выделяется train для подробного EDA и обучения. IQR-пороги рассчитываются на внешнем train до внутренней CV, а не внутри каждого fold. Один test используется для нескольких сценариев; для следующего выбора моделей нужен отдельный validation или новый отложенный набор. Значения OLS в конце Lasso-ячейки повторены константами, это не дополнительный запуск. Случайная подвыборка для Shapiro–Wilk не имеет фиксированного seed.

При подготовке исключены демонстрация resample по искусственной дате, отдельный Plotly-пример и дублирующая демонстрация кодирования BMI. Они не нужны для сохранённого моделирования. Удалены незаполненные теоретические вопросы и административные инструкции. Выводы приведены к фактическим метрикам; улучшение от Lasso не заявляется.

## Used cars: регрессия и ансамбли

[Ноутбук](../notebooks/used_cars_ensembles.ipynb) · [Метрики CSV](../results/used_cars_metrics.csv)

Данные — [Used Cars Prices in UK на Kaggle](https://www.kaggle.com/datasets/muhammadawaistayyab/used-cars-prices-in-uk). Фактически исходное задание скачивает `used_cars_UK.csv` с [Google Drive](https://drive.google.com/uc?id=1Cdek-lsS3-XiDFtD5PzgXNsy3gvd_Rd-). Получите CSV и поместите его в `data/used_cars_UK.csv` в корне репозитория либо задайте `USED_CARS_CSV` до запуска Jupyter. Автоматический shell-download заменён проверкой файла; алгоритмы подготовки и обучения не менялись.

Подготовка удаляет неиспользуемые колонки, заполняет пропуски, объединяет редкие категории в `Other` и выполняет one-hot encoding. Внешнее разбиение — train/test 80/20, seed 42. В blending train дополнительно делится 80/20 на base/meta: сохранены размеры 2358 и 590 строк, 37 признаков.

Выполненные сравнения на общем test:

- Linear regression: RMSE **2258,92**, MAPE **35,71%**.
- kNN (k=5): **2291,32 / 27,81%**; decision tree: **2269,76 / 31,83%**.
- Bagging по умолчанию: **1791,49 / 23,35%**.
- Настроенный bagging: **1794,78 / 25,19%**. Поиск: 360 конфигураций, пять folds; лучший внутренний CV RMSE **1497,26**.
- Blending: **1979,44 / 28,63%**; stacking: **1984,19 / 26,61%**.
- Stacking с настроенным bagging среди базовых моделей: **1767,68 / 23,69%**.

В ноутбуке также сохранён выполненный подбор decision tree, его применение в stacking и сравнение метамоделей LinearRegression, RandomForestRegressor и GradientBoostingRegressor из sklearn. Результаты не объединены в рекламное утверждение о приросте качества.

**Ограничения.** Средние для импутации и частоты редких категорий рассчитаны на всём наборе до split: информация о test входит в подготовку. Scaler для linear/kNN находится в Pipeline, однако это не устраняет предшествующее ограничение. Разные ансамбли и настройки сравниваются на одном test; для строгого выбора необходима новая оценка с подготовкой данных внутри folds и отдельной финальной выборкой. Весам линейной метамодели blending не заданы ограничения на знак или сумму.

### Собственный random forest на insurance

Последний выполненный блок использует отдельную задачу: классификацию четырёх регионов `region` по insurance. Удалён один дубликат, остаётся 1337 строк; stratified split 80/20, seed 42: 1069 train / 268 test. Своя реализация использует готовые `DecisionTreeClassifier`, bootstrap объектов и усреднение вероятностей. Это реализация ансамбля, не деревьев с нуля.

Сохранённый test: sklearn RF accuracy **0,3843**, macro-F1 **0,3787**; свой RF **0,3955 / 0,3867**. IQR-клиппинг здесь выполнен до split. Небольшая разница на одном наборе не доказывает превосходство или общую корректность реализации; обработка редких классов внутри bootstrap отдельно не проверена.

Из копии исключены незавершённые CatBoost/Optuna-разделы и невыполненные XGBoost/LightGBM/SHAP/экспортные демонстрации, а также повторные варианты того же RF. Они доступны по ссылке на исходник в PROVENANCE и не представлены как выполненная часть портфолио.

## Insurance: кластеризация

[Ноутбук](../notebooks/insurance_clustering.ipynb)

Используется тот же `insurance.csv`, 1338 строк. Шесть признаков: age, bmi, children, charges и бинарные кодировки sex/smoker. `region` исключён из признаков и используется только как внешняя разметка ARI. Это исследование всего набора без train/test.

Собственный k-means сошёлся за 13 итераций при одной фиксированной инициализации. Сохранённый ARI относительно региона: собственный k-means **0,0019**, sklearn KMeans **0,0019**, AgglomerativeClustering **0,0027**, DBSCAN **−0,0013**. Для sklearn KMeans после StandardScaler и PCA до двух компонент — **0,0025**.

![PCA: регионы и найденные кластеры](../results/insurance_clustering_pca.png)

Значения около нуля показывают отсутствие соответствия именно региональной разметке при этих настройках; они не доказывают отсутствие любой другой структуры. Эффекты PCA и scaling отдельно не исследованы. DBSCAN после scaling не запускался. Собственная реализация k-means не обрабатывает пустые кластеры и не проверена на серии seed.
